# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Agent Skills for WordPress — portable Markdown bundles that teach AI coding assistants WordPress-specific patterns. Skills live under `skills/`, are authored here, and are distributed via a build step into target-specific directories for Claude Code, Cursor, VS Code/Copilot, and OpenAI Codex.

## Key commands

All scripts run from the repo root with Node.js (no `npm install` needed):

```bash
# Scaffold a new skill
node shared/scripts/scaffold-skill.mjs <skill-name> "<description>"

# Validate all skills (frontmatter + triage contract)
node eval/harness/run.mjs

# Build distribution packages into dist/
node shared/scripts/skillpack-build.mjs --clean

# Install skills globally for Claude Code (~/.claude/skills/)
node shared/scripts/skillpack-install.mjs --global

# Install into another repo (e.g. a WordPress project)
node shared/scripts/skillpack-install.mjs --dest=../some-wp-repo --targets=claude,cursor

# Preview install without writing files
node shared/scripts/skillpack-install.mjs --global --dry-run

# Refresh upstream index data (WordPress/Gutenberg version matrices)
node shared/scripts/update-upstream-indices.mjs
```

## Skill structure

Each skill directory under `skills/` must follow this layout:

```
skills/<skill-name>/
├── SKILL.md              # Required. Short, procedural instructions.
├── references/           # Optional. Deep-dive docs linked from SKILL.md.
│   └── *.md
└── scripts/              # Optional. Deterministic detection/validation helpers.
    └── *.mjs
```

### SKILL.md requirements

Every `SKILL.md` must have YAML frontmatter with three fields:

```yaml
---
name: <skill-name>          # Must match the directory name exactly
description: "..."          # ≤1024 chars; used by AI to decide relevance
compatibility: "Targets WordPress 6.9+ (PHP 7.2.24+). ..."
---
```

The `compatibility` field must include both `WordPress 6.9` and `PHP 7.2.24` — the eval harness enforces this.

Required sections in the body: **When to use**, **Inputs required**, **Procedure**, **Verification**, **Failure modes / debugging**, **Escalation**.

### Eval scenarios

Each skill should have at least one scenario under `eval/scenarios/<skill-name>.json`:

```json
{
  "name": "Human-readable title",
  "skills": ["skill-name-1", "skill-name-2"],
  "query": "The user prompt that triggers this skill",
  "expected_behavior": ["Step 1: ...", "Step 2: ..."],
  "success_criteria": ["Criterion 1", "Criterion 2"]
}
```

## Architecture

### Routing model

`skills/wordpress-router` is the entry point. It runs `skills/wp-project-triage/scripts/detect_wp_project.mjs` to classify a repo, then delegates to domain skills (e.g. `wp-block-development`, `wp-plugin-development`). When adding a new skill, consider whether `wordpress-router/references/decision-tree.md` needs updating.

### Build and distribution

`shared/scripts/skillpack-build.mjs` copies each skill directory from `skills/` into four target layouts under `dist/` (no symlinks — Codex ignores them). The install script then copies from `dist/` to the destination. The `dist/` directory is gitignored.

### Shared references

`shared/references/` contains JSON index files (WordPress/Gutenberg version matrices) that are regenerated by `update-upstream-indices.mjs` and consumed by skill scripts.

## Authoring rules

- Keep `SKILL.md` short and procedural; push depth into `references/` files.
- Keep `references/` files at most 1 hop from `SKILL.md` (no deep chains).
- Use scripts for anything an AI would otherwise "guess" (version detection, project layout checks).
- Target WordPress 6.9+ and PHP 7.2.24+; avoid legacy patterns (Classic themes, pre-Gutenberg APIs).
- Run `node eval/harness/run.mjs` before submitting a PR.
